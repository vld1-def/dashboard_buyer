Facebook tokens

System user tokens: where the dashboard reads stats from, and what it pauses campaigns with.

The token is checked against Facebook the moment you add it — you see its permissions, expiry and how many ad accounts it can reach. Nobody can read it back afterwards, you included: the database grants no access to that column, and only the server function retrieves it. Where to get a token: see FB_TOKENS.sql.

What those tokens actually pull — cabinet state, today's spend, what is live inside — lives on the Cabinets page, together with the Sync now button. Name a token Agent_Browser_BMid and the dashboard fills in the agent, the browser number and the BM for every cabinet it sees.

Sync schedule

How often the dashboard walks the cabinets — and, with it, how often rules get a chance to act: they run right after each sync, on a snapshot that is seconds old. The schedule itself ticks every 15 minutes; these two numbers decide when a tick actually does the work, so you change the pace here and never in SQL.

Night lasts from / to —

Set both to the same hour and there is no night — the daytime pace runs around the clock. 15 minutes is as fast as the schedule ticks, so a smaller number changes nothing until you change the schedule too (the alter_job note at the bottom of FB_SYNC_CRON.sql). Facebook counts even refused requests against the limit, so faster is not always more data: 15 minutes costs twice what 30 does.

Comments under ads

The scheduled run walks the cabinets, finds comments written since it last looked, and sends them to Telegram.

Hiding is reversible: only its author keeps seeing the comment, and they are not told. You can put it back from the cabinet panel at any time. Deleting is never automatic — that stays a button you press yourself, because there is no way back from it.

The first pass over a cabinet hides nothing and reports nothing: it only notes the time. Otherwise turning this on would bury you in comments from six months ago and hide half a year of conversation in one go.
