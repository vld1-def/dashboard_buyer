# check-domains

Перевіряє домени з сервера й пише результат назад у таблицю `domains`.

## Навіщо окрема функція

Дашборд — статична сторінка. Код відповіді чужого домена вона прочитати
не може: CORS блокує читання, а режим `no-cors` повертає статус `0` і
для `200`, і для `404`. Тобто з браузера видно рівно одне — відповів
домен чи ні.

Тут запит іде з сервера, де CORS не існує. Звідси справжній код
відповіді, і звідси ж можливість спитати Google Safe Browsing.

## Розгортання

```bash
supabase functions deploy check-domains
```

Мітки Safe Browsing — необов'язково. Без ключа функція працює, просто не
ставить статус `danger`:

```bash
supabase secrets set SAFE_BROWSING_KEY=AIza...
```

Ключ береться в Google Cloud Console: увімкнути **Safe Browsing API** →
Credentials → API key.

## Як викликається

Кнопка **Deep check** на сторінці Domains. Запит іде з токеном того, хто
залогінений, і функція створює клієнт Supabase саме з цим токеном — тож
RLS лишається в силі й чужих доменів вона не бачить.

Ключ сервісної ролі тут свідомо **не** використовується: інакше будь-хто,
хто докличеться до функції, отримав би доступ до чужих рядків.

## Порціями

За один виклик перевіряється до 200 доменів — Edge Function обмежена в
часі, і чесна порція краща за обрив посеред роботи. У відповіді є `more`
і `next`; дашборд ходить по колу з курсором `after`, поки `more` не стане
`false`.

## Статуси

| Код | Статус | Що означає |
|---|---|---|
| 2xx, 3xx | `ok` | відповідає |
| 404 та інші 4xx | `notfound` | домен живий, але сторінку не віддає |
| 5xx | `down` | сервер відповідає помилкою |
| немає відповіді | `down` | DNS, сертифікат, відкинуте з'єднання, таймаут |
| — | `danger` | у списку Safe Browsing |

`danger` перекриває код відповіді: домен у списку Google віддає звичайні
`200`, і саме тому сам ти його не помітиш.

`HEAD` пробується першим; якщо сервер відповідає `405` або `501` —
повторюємо `GET`, бо це не діагноз домена, а невміння сервера.
